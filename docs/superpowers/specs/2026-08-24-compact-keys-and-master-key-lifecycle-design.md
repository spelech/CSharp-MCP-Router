# Design Specification: Compact AppKey Taxonomy & Master Encryption Key Lifecycle

**Date:** 2026-08-24  
**Status:** Approved  
**Target Release:** v4.35.0  
**Scope:** Gateway Core, Credential Services, Database Encryption Helpers, Settings Web UI & Admin MCP, Setup Skills, Documentation & Test Suites.

---

## 1. Executive Summary

This specification addresses two key usability and security requirements for CSharp-MCP-Router:
1. **Compact & Semantic AppKey Taxonomy**:
   - Replace 108-character hexadecimal tokens with concise, friendly ~32-character Base62 tokens with explicit semantic prefixes (`mcp-adm-`, `mcp-glb-`, `mcp-{domain}-`, `mcp-usr-`, `mcp-srv-`).
   - Implement interactive Admin AppKey prompting and custom `ROUTER_ADMIN_KEY` environment seeding.
2. **Master Encryption Key Transparency & Lifecycle Management**:
   - Provide direct HashiCorp Vault bootstrapping for enterprise multi-replica clusters.
   - Track `KeySource` (`External`, `AutoGenerated`, `Configured`).
   - In the Web UI / Admin MCP, surface an actionable warning when `KeySource == AutoGenerated`, allowing homelab/standalone administrators to set a permanent Master Key with atomic database re-encryption.
   - Lock / hide configuration when `KeySource` is externally managed.

## 2. Compact AppKey Taxonomy & Cryptographic Design

### 2.1 Prefix Scheme & Format
AppKeys are formatted as `{prefix}{selector_8chars}-{secret_16chars}` (total length ~32–34 characters):

| Key Type | Prefix | Description | Example |
| :--- | :--- | :--- | :--- |
| **Admin Key** | `mcp-adm-` | System administrator with full control (`all`, `admin`) | `mcp-adm-Xk9L2mPq-7vN3wZ8aB1cE4fG9` |
| **Global Key** | `mcp-glb-` | Gateway-wide tool execution across all servers | `mcp-glb-R4t8W1yU-9pM2nQ6sD8fH3jK5` |
| **Domain Scoped** | `mcp-{domain}-` or `mcp-grp-` | Restricted to a specific group/domain | `mcp-devops-T5v7P2mX-3kL9aB1cE4fG8hJ` |
| **Personal / User** | `mcp-usr-` | Personal user key tied to a specific username/SID | `mcp-usr-A7d9F2kL-8xP1mC3vT5bN6mQ2` |
| **Server Scoped** | `mcp-srv-` | Restricted to a single target backend MCP server | `mcp-srv-docker-K4m8X2pL-9vN3wZ8aB1cE` |

### 2.2 Entropy & Storage
- **Cryptographic Strength**: Generated using `RandomNumberGenerator` across Base62 alphabet (`[A-Za-z0-9]`), providing **~143 bits of entropy**.
- **Database Indexing**: The `KeyPrefix` column stores `{prefix}{selector_8chars}` for sub-millisecond prefix-indexed lookups.
- **Hash Verification**: The complete token is validated via constant-time comparison of its SHA-256 hash against `AppKeys.EncryptedKey`.
- **Backward Compatibility**: `AppKeyAuthenticationHandler` seamlessly supports legacy keys and custom formatted tokens.

### 2.3 Declarative & Interactive Seeding (`ROUTER_ADMIN_KEY`)
- `ClientAppKeySeeder` inspects `IConfiguration["ROUTER_ADMIN_KEY"]` or `IConfiguration["MCP_ADMIN_KEY"]`.
- If provided, seeds that key for `admin` on initial database creation.
- If omitted and no admin key exists, seeds an auto-generated compact `mcp-adm-` key.

## 3. Master Encryption Key Lifecycle & Enterprise Bootstrapping

### 3.1 Key Resolution Hierarchy & `KeySource` Detection
[`DbKeyHelper`](file:///containers/dev/csharp-mcp-router/Infrastructure/Secrets/DbKeyHelper.cs) detects and reports the origin of the active encryption key:

1. **Vault Bootstrapping (`KeySource.External`)**:
   - If `VAULT_ADDR` is present, connects to HashiCorp Vault (Token, AppRole, or Kubernetes Service Account auth) and fetches `secret/data/mcp-router/master-key`.
2. **Environment Variable (`KeySource.External`)**:
   - `ROUTER_SECRET`, `ROUTER_MASTER_KEY`, or `DB_ENCRYPTION_KEY`.
3. **Secret File Mount (`KeySource.External`)**:
   - `ROUTER_MASTER_KEY_FILE` or standard paths (`/run/secrets/router_master_key`).
4. **Existing Keyfile (`KeySource.KeyFile` / `KeySource.Configured`)**:
   - `./data/.master.key` exists from prior configuration.
5. **Auto-Generated Keyfile (`KeySource.AutoGenerated`)**:
   - Auto-generated 256-bit key saved to `./data/.master.key` on first boot.

### 3.2 Dynamic Database Re-Encryption (Settings API & Web UI)
When an admin sets a custom Master Key via `POST /api/config/master-key` or `/admin` MCP tool `manage_system(action: "set_master_key", newKey: "...")`:
1. **Verification**: Backend validates that `KeySource != External`.
2. **Atomic Transaction**:
   - Decrypts all encrypted rows in `SecretProviders`, `AuthProviderConfigs`, `Servers`, and `UserSecrets` using the current active key.
   - Re-encrypts all rows using the new master key.
   - Overwrites `./data/.master.key` with the new key.
   - Updates in-memory key cache and sets `KeySource = Configured`.
3. **Web UI Status**:
   - Auto-generated warning alert is dismissed.
   - Master key status badge updates to `🔒 Master Key: Configured`.

## 4. Setup Skill (`mcp-router-setup`) Enhancements

1. **Phase 5 Interactive Prompt**:
   - Prompt user: *"Enter your desired Admin Key for agent/API access (or press Enter to auto-generate a compact key like `mcp-adm-Xk9L2mPq-7vN3wZ8aB1cE4fG9`):"*
   - Sets `ROUTER_ADMIN_KEY` in `.env` / `docker-compose.yml`.
2. **Master Key Configuration**:
   - Default: Omit `ROUTER_MASTER_KEY` from `.env`, informing the user that the gateway manages the master key with in-app configuration/re-encryption support.
   - Vault Mode: If `VAULT_ADDR` is detected, configure Vault bootstrapping directives.
