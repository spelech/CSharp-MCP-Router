Plan for Jules: Issue #34 - Target User SID for Admin-Minted Keys

Goal: In `AppKeysController.CreateAppKey`, when an admin mints a key for another user, store the target user's SID instead of the admin's SID as the `OwnerSid`.

Implementation Steps:

1. In `Controllers/AppKeysController.cs` inside `CreateAppKey`:
   - Around line 159, the `targetUser` is determined. If `targetUser` is different from `currentUser`, the `ownerSid` variable (which currently defaults to the admin's SID) needs to be updated.
   - Inject or resolve `ILdapService` from the request services and query the target user's SIDs.
   - Example implementation logic:
     ```csharp
     if (!targetUser.Equals(currentUser, StringComparison.OrdinalIgnoreCase))
     {
         var ldapService = HttpContext.RequestServices.GetService<McpRouter.Core.Identity.ILdapService>();
         if (ldapService != null)
         {
             var targetSids = await ldapService.ResolveUserSidsAsync(targetUser);
             var primarySid = targetSids.FirstOrDefault();
             if (!string.IsNullOrEmpty(primarySid))
             {
                 ownerSid = primarySid;
             }
         }
     }
     ```
   - This updated `ownerSid` will automatically flow into the database insert (`appKey.OwnerSid = ownerSid;`) and the audit log message at the bottom of the method (`ownerSid={ownerSid}`), fixing the attribution bug entirely.
