{"body":"## Description\nImplement native support for automatically injecting the authenticated user's session identity using the `X-Forwarded-User` header (e.g., `X-Forwarded-User: DOMAIN\\User`) into outgoing HTTP/SSE transport requests.\n\n## Motivation\nCurrently, the router can inject a global static Service Account API Key (via Vault/Registry) to authenticate the Router to a backend, but it doesn't automatically forward *who* is initiating the tool call. By injecting the `X-Forwarded-User` header, downstream MCP servers can implement the **Trusted Gateway Pattern**—bypassing the need for dynamic JWTs/Kerberos while still enforcing fine-grained Row-Level Security (RLS), User-Based RBAC, and accurate audit logging based on the human/IDE executing the tool.\n","title":"Identity-Header Propagation (Trusted Gateway Pattern) via X-Forwarded-User"}
