Plan for Jules: Issue #35 - Cross-Platform SID Resolution

Goal: Remove the Windows-only dependency (`WindowsIdentity`) in `ActiveDirectoryIdentityProvider.cs` and rely entirely on pure-LDAP for SID resolution on non-Windows hosts.

Implementation Steps:

1. Update `Core/Identity/ActiveDirectoryIdentityProvider.cs` (Lines ~34-69):
   - Modify the identity check to accept any authenticated identity, not just `WindowsIdentity`. Change: 
     `if (httpContext.User.Identity is WindowsIdentity winIdentity && winIdentity.IsAuthenticated)`
     to:
     `if (httpContext.User.Identity != null && httpContext.User.Identity.IsAuthenticated)`
   - Extract the `username` from `httpContext.User.Identity.Name`.
   - Attempt to extract the primary SID and Group SIDs from claims if `httpContext.User.Identity` is a `ClaimsIdentity` (e.g., checking standard SID claim URIs).
   
2. Enhance the LDAP Fallback Logic:
   - If the identity was a `WindowsIdentity` (which still works on Windows), keep the existing fast-path logic to grab the SID/Groups.
   - For all platforms, if `ldapService != null`, call `await ldapService.ResolveUserSidsAsync(username)` (which already does the heavy lifting of parsing byte-arrays to SID strings without Windows dependencies).
   - Merge the LDAP SIDs with any claims-based SIDs. If the primary SID is missing (because we aren't on Windows and there were no claims), take the first SID returned by the LDAP service as the primary `Sid`, since `LdapActiveDirectoryService.cs` always inserts the user's `objectSid` before their `tokenGroups` SIDs.

3. Update Documentation:
   - Remove the limitation from `DEPLOY.md` that states Active Directory SID resolution is Windows-only.
